# AlcoBarrier

Приложение контроля трезвости сотрудников на проходной: читает результаты алкотестера,
сопоставляет карту с сотрудником в Innerage (Sigur), ведёт журнал замеров и управляет
состоянием карты в СКУД.

.NET Framework 4.8, WinForms, SQLite (Microsoft.Data.Sqlite), System.Text.Json.

## Состав

| Компонент | Назначение |
|---|---|
| `MainForm` | Окно, опрос алкотестера, таймеры событий и синхронизации, журнал в таблице |
| `Requests/RequestAlcoReader` | HTTP-клиент алкотестера (`http://<ip>:443/cmd`, JSON-команды `getInf`, `getLogInf`, `getLog`) |
| `Requests/RequestInner` | REST-клиент Innerage: `SystemInfo`, `User/User?FullObject=True`, `User/AddOrUpdate` |
| `Requests/InnerageCommandBuilder` | Безопасная сборка XML-команды `AddOrUpdate` (экранирование значений) |
| `Headers/InnerageXmlParser` | Разбор XML Innerage: сотрудники/карты, тексты `SystemInfo`/`CommandProgress` |
| `Headers/MyJson` | Разбор JSON алкотестера, выбор кода карты (Wiegand) |
| `DB/*` | SQLite-слой: `employees`, `events`, `loguser`, `settings` |
| `Logger` | Файловый лог |

## Бизнес-логика

### 1. Замер и сопоставление карты

Алкотестер опрашивается непрерывно (базовая пауза 250 мс, при сбоях — до 5 с).
Когда в памяти устройства появляется новая запись (`LastRecord` изменился),
приложение читает её командой `getLog`.

Замером считаются события устройства с кодом **4** или **5**
(по протоколу: результат ниже/равен порогу или выше порога).

Код карты берётся из полей `WiegandLSB`/`WiegandMSB` и проверяется в `employees`
по нескольким кандидатам: младшие 16 бит, вариант со сдвигом на бит (если в коде
остались биты чётности) и полный код. Совпадение с `employees.code` определяет сотрудника.

### 2. Журнал замеров

Каждый замер сохраняется в `loguser` (дата, время, концентрация, сотрудник, номер карты).

- **Карта найдена** — запись содержит сотрудника и номер карты.
- **Карта не передана устройством** (`WiegandLSB` пуст или 0) — запись сохраняется
  с `cardnum = "0"` и `user = NULL`; блокировка не создаётся. Один раз за запуск
  пишется предупреждение с подсказкой проверить настройку записи Wiegand-кодов
  в память событий блока сопряжения (по умолчанию она запрещена).
- **Карта передана, но сотрудника нет в `employees`** — запись сохраняется,
  в лог пишется `WARNING` с сырыми `WiegandLSB`/`WiegandMSB` и проверенными кодами;
  блокировка не создаётся.

### 3. Блокировка карты

Для замера с известным сотрудником создаётся задача в `events`:

```
blockdate = момент замера + BlockHour часов + BlockMinute минут
```

Сразу после создания задачи приложение переводит карты всех задач в состояние
**Active** (команда `AddOrUpdate`, `State=Active`) — это поведение зафиксировано
требованиями и не является ошибкой.

Дальше работает таймер (каждые 5 с):
когда `blockdate` наступил, карта переводится в состояние **Unused** (`State=Unused`,
блокировка), задача из `events` удаляется.

**Автоматической разблокировки нет:** после блокировки карта остаётся `Unused`,
снимать блокировку нужно вручную в Innerage (или снова через тест, если так
предусмотрено регламентом).

Если Innerage недоступен, задача не теряется: она остаётся в `events` и повторяется
с нарастающей паузой (5, 10, 20, 40, 80, 160, 300 с), удаляется только после
подтверждённой блокировки.

### 4. Сотрудники (синхронизация)

Источник — Innerage `GET /restApi/v2/User/User?FullObject=True` (XML).
В `employees` хранится **одна строка на карту**: имя пользователя, адрес (`iduser`),
номер карты (`code`), данные карты (`hex`), идентификатор (`id`), шаблон (`CardTemplate`).

Синхронизация выполняется:

- при старте приложения;
- периодически с интервалом `SyncMinutes` минут (настройка в `settings.db`);
- интервал `<= 0` отключает периодическую синхронизацию (остаётся только стартовая).

Таблица `employees` заменяется атомарно в одной транзакции. Если ответ Innerage
не получен, не разобран, не содержит ожидаемой структуры или не содержит карт,
локальная база **не изменяется** (в лог пишется причина).

### 5. Настройки

Хранятся в `settings.db` (таблица `setInner`, одна строка):

| Поле | Смысл |
|---|---|
| `IpInnerage` | адрес Innerage, допускается `host:port` |
| `authorization` | заголовок `Authorization` (например, `Basic ...`); пусто — не отправляется |
| `key` | заголовок `API-KEY`; пусто — не отправляется |
| `BlockHour`, `BlockMinute` | через сколько от замера карта блокируется |
| `SyncMinutes` | интервал периодической синхронизации, минуты (по умолчанию 60) |

Таблица `setAlco` — адрес алкотестера (`IpAddress`).

При первом запуске подставляются значения по умолчанию:
`127.0.0.1`, пустые `authorization`/`key`, блокировка `0 ч 5 мин`, синхронизация 60 мин.
Менять настройки сейчас можно только SQLite-клиентом (UI настроек нет) и **после
перезапуска приложения** — значения читаются один раз при старте.

## Базы данных

Файлы `*.db` лежат в текущем рабочем каталоге процесса (рядом с `logs/`).
Схема создаётся/дополняется при старте (`CREATE TABLE IF NOT EXISTS` + миграции колонок).

- `employees(idkey, name, iduser, code, hex, id, CardTemplate)` — карты сотрудников.
- `events(id, iduser, code, hex, cardtamplate, date, blockdate)` — задачи блокировки.
- `loguser(id, date, time, promille, user, cardnum)` — журнал замеров.
- `settings(setInner, setAlco)` — настройки.

Все запросы параметризованы; SQLite работает в режиме WAL с `busy_timeout = 5000`.

## Логи

`logs/alco-YYYY-MM-DD.log` в текущем рабочем каталоге, один файл на день.
Пишутся: старт/настройки, результаты синхронизации и её ошибки, статусы блокировок,
потеря/восстановление связи с алкотестером, неизвестные карты, ошибки таймеров.

## Сборка

Требования: Visual Studio 2022 (или Build Tools) с .NET Framework 4.8, NuGet-пакеты
восстанавливаются в `AlcoBarrier\packages` (папка проекта).

```powershell
msbuild AlcoBarrier.sln /t:Rebuild /p:Configuration=Debug
```

Результат: `AlcoBarrier\bin\Debug\AlcoBarrier.exe`. Нативные библиотеки `e_sqlite3`
копируются в `bin\Debug\runtimes\win-*` автоматически (импорт targets из пакета
`SQLitePCLRaw.lib.e_sqlite3`).

## Тесты

Харнесс-скрипты (без отдельного тестового проекта):

```powershell
powershell -ExecutionPolicy Bypass -File tests\run-xml-parser-tests.ps1
```

Скрипт собирает проект, компилирует `tests\XmlParserHarness.cs` против
`bin\Debug\AlcoBarrier.exe` и проверяет разбор XML Innerage и сборку команд:
безопасность (XXE, entity-бомбы), namespace/комментарии/пробелы, несколько карт,
`Ref` на разной глубине, дубли, невалидные ответы, экранирование XML-команды.

## Ограничения и особенности

- Приложение должно быть постоянно запущено: службы/автозапуска/сторожа нет,
  закрытие окна останавливает контроль, второй экземпляр не блокируется.
- Пути БД и логов зависят от текущего каталога запуска.
- Настройки меняются только в SQLite и применяются после перезапуска.
- Обмен с Innerage и алкотестером идёт по HTTP (эксплуатация — в защищённой сети).
- Автоматической разблокировки после `blockdate` нет (по требованиям).
- Ретенции нет: `loguser` и логи растут, таблица замеров в окне не ограничена.
